One file. One app. Any host.

A plug is a single signed file that snaps into a website, a HUD, a game world or a desktop. It can only touch what it declared. The host holds no user data. Change one byte and it won't run.

In plain words

What is this, in 30 seconds

The problem

Today every app is stuck to one website, one app store or one device. When you add someone else's tool to your site, it can usually see and do far more than it needs to, and your users' data ends up on someone else's servers.

The idea

Think of a USB plug for software. A plug is one file holding a small app. Any socket (a website, a HUD, a game, a desktop) can run it. The socket decides what it's allowed to touch. The plug can't do anything more.

Why you can trust it

The maker seals the file with a digital signature. If anyone changes a single byte, it won't run. It only gets what it asked for up front, and you approve that. Everything it tries is written down in a report card you can read.

  WITHOUT A PLUG                           WITH A PLUG

  your site  <----- tool                    your site
     |  sees everything                    +------------+
     |  sends your users' data             |  SOCKET    |  decides, logs
     |  anywhere it likes                  |  +------+  |
     v                                     |  | plug |  |  only what it asked,
  someone else's servers                   |  +------+  |  only what you allowed
                                           +------------+

Words used here

Ten words used on this page

The whole idea in ten words. Each one means exactly this, nothing more.

plug
one file that holds one small app (a .plug file)
socket / host
the place a plug runs: a web page, a HUD, a game, a desktop
manifest
the plug's label (plug.json): what it is, who made it, what it may touch
permissions
the list of things it may touch. Not on the list = blocked
signature
the maker's digital seal. Change the file and the seal breaks
fingerprint
a short code worked out from a file's exact bytes. One byte different = a different fingerprint
sandbox
the box the plug runs in: it can't see the page around it, your cookies, or your files
gate
checks every single thing the plug asks for, answers yes or no, and writes it down
gateway
the only road to the internet, and only to addresses the plug declared
watchdog
keeps watching while it runs, and pulls the plug if it misbehaves

How it works

From a folder to a running, boxed-in app

Every arrow is a check. If any check says no, the plug stops there and tells you why in plain words.








What's inside a plug


Four parts, one file


A plug is one file you can pass around. Open it up and there are four parts. The permissions list decides everything the app inside may touch.




  hello.plug
  |
  +-- plug.json    what it is, who made it,
  |                what it's allowed to touch
  |
  +-- build.json   fingerprint of every file
  |
  +-- app/         the app itself (one page)
  |
  +-- signature    the author's seal over all
                   of the above



  "permissions": {
    "network": ["api.example.com"],
    "storage": "64KB",
    "events":  ["hello.ping"]
  }

  Not listed = not reachable.
  No camera. No mic. No location.
  No cookies. No peeking at the page.










Layers


Each layer is checked by the next


Before a plug (a signed one-file app) runs, it has to pass seven checks, one inside the other. Like an onion: fooling one layer isn't enough. All of them have to agree, in the same file, at the same time.


  +-------------------------------------------------------------+
  | 7 WATCHDOG   keeps watching; misbehave and it pulls the plug |
  |  +-------------------------------------------------------+  |
  |  | 6 GATEWAY  internet only to declared hosts, never home |  |

  |  |  | 5 WITNESS  two separate checkers must agree     |   |  |

The gate


A yes/no circuit, live


The gate sits between a plug (a boxed-in app) and everything outside it. Every message the plug sends goes in. Exactly one answer comes out, with a reason, and it's written down. The report card is built only from that record.















Fastener rules


Grips harder when pulled. Slides in, never back out.


Two extra safety rules, named after real fasteners. A wall anchor grips tighter the harder you pull: an app that keeps asking for things it can't have gets less and less. A barbed fitting only goes one way: permissions only shrink, versions only go up, and nobody else can take over an app's name.




  WALL ANCHOR (pull harder, grip tighter)

  refused requests:  0    1    2    3    4
  allowance / min:  30   15    7    3    1
                    ##### ###  ##   #    .

  at 20 refusals: plug pulled, every door shut
  behave well:    nothing ever tightens



  BARBED FITTING (one way only)

  permissions   wide  >>>--->  narrow    <-- x
  versions      1.2   >>>--->  1.3       <-- x
  plug name     yours >>>--->  yours     <-- x anyone else

  narrowing is fine, widening is refused
  upgrading is fine, rolling back is refused










Fit check


Drop anything in. Find out before you change a thing.


It reads your file or folder (never changes it) and says what fits, what needs a tweak, and why.


$ python tools/fit.py my-game/

It looks like: a folder
Start page: index.html

[fix] saves data in the browser   (index.html line 4)
       why: a plug runs boxed in, so browser storage is blocked
       fix: use the socket's storage.set and add "storage": "1MB"
[fix] talks to the internet directly   (index.html line 5)
       why: direct network calls are blocked; they go through the gateway
       fix: send net.fetch to the socket, list the host in permissions
[no]  sends the page somewhere else   (index.html line 9)
       why: a plug that navigates away gets pulled by the watchdog
       fix: show and hide sections instead of changing pages

VERDICT: doesn't fit yet. Start with the [no] items.
(Your original was only read, never changed.)_
